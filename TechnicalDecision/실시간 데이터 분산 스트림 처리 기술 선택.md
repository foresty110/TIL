# 현재 defomo 시스템의 문제점 

## 현재 구조: 수집 서버에서 하는일 
- WebSocket 데이터 수신
- 종목별 데이터 분류
- 집계 상태 관리
- 최소가·최대가 계산
- Kafka 발행 시점 결정

## 문제점 1: 원본 데이터가 사라진다. 
가격이 언제 조건을 만족했는지 알 수 없다, 마지막 현재 가격을 알 수 없다. 
단순히 특정 구간에서 한 번이라도 목표 가격을 넘었는지 판단하는 기능이라면 ok

## 문제점 2: 배치 주기만큼 알림이 늦어진다
조건 충족 시점과 처리 시점이 달라진다, 배치 주기가 길수록 알림 지연이 커진다, 배치 집계 방식에 따라 알림 판단에 필요한 정보도 사라진다

## 문제점 3: Java 프로그램이 장애를 겪으면 집계 데이터가 유실될 수 있다 
이미 Kafka에 들어온 데이터에 대해서는 저장 및 재처리 기능을 제공하지만, Kafka에 발행하기도 전에 Java 메모리에서 사라진 데이터는 복구해 주지 못한다.

# Spark Structured Streaming
- Micro-batch:  들어온 스트리밍 데이터를 작은 배치 단위로 나누어 처리하는 방식
